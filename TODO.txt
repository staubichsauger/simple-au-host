Audio jitter improvements

1. Replace sleep-polling worker loops with event-driven wakeups.
   - Current worker loops in simple mode and multi-track buffered modes poll ring-buffer availability and sleep for 1 ms.
   - Change this to a signal/wait model so workers wake immediately when a full block is ready.

2. Pre-roll buffered output before starting playback.
   - Ensure at least one processed block is queued before the output path begins consuming it.
   - This should reduce startup underruns and first-block clicks.

3. Keep true realtime paths on the device callback thread.
   - Direct low-latency paths should continue to process inline on the audio callback.
   - Worker-thread paths should be treated as buffered/stability-oriented modes.

4. Improve worker scheduling after removing sleep-polling.
   - Revisit thread priority/QoS once the worker wakeup model is event-driven.
   - Only tune scheduling after the basic jitter source is removed.

Suggested implementation order
- First: simple mode worker-thread path
- Second: multi-track buffered and broadcast worker paths
- Third: optional scheduling/priority tuning
